# EMBODY 1.0.0-rc1 — local release review

This candidate adds a coherent **local trusted rail debugging workflow**. It is not
an unrestricted robotics release or a successful live GPT qualification.

## Delivered

- Default project → physical context/source → native verification → deterministic
  investigation → typed review → explicit numerical save → rerun → evidence export.
- Existing Toolkit snapshots, registered controller, compiler, native engine,
  fresh replay and independent result reader reused unchanged.
- Strict JSON source review, exact-head saves, discard, restore-as-new-review,
  interrupted-operation preservation and immutable run/snapshot associations.
- Actual sample-linked 3D playback and distinct physical/replay/current-head status.
- Deterministic assistant citations and an analytical authority-only proposal,
  visibly separate from GPT/model authorship.
- Existing studio and advanced tools remain separately accessible.

## Compatibility and limitations

The new default UI and launcher alter application source bindings. Historical
qualification/consent source hashes must not be reused. Native controller/models,
requirements, historical heads, accounting and raw evidence are preserved.

Editable source is bounded numeric `robot.json`, not arbitrary Python. Numerical
save is not mechanical/controller installation. Simulation is finite rigid-proxy
verification, not hardware, manufacturing, material or universal safety certification.
Circuit information is not coupled to this rail powertrain.

Live GPT qualification remains unverified after the canonical-ID repair. The
historical failed answer and sandbox bootstrap blocker remain recorded as such;
no provider test, paid reservation or credential access is part of this candidate.

Some unrestricted historical test suites depend on private artifacts not distributed
in the public checkout. The supported public regression policy is documented, and
those archival failures remain visible separately. This candidate must not be
advertised as an all-history/all-platform/all-model test pass.

build, startup, real Chrome workflow, exact JSON export and independent native
read-back passed. The two browser cases reproduced the measured clearance FAIL
(0.003 m at 2.0 N) and PASS (0.071570625 m at 2.1 N), with unchanged requirements.
These are deterministic local experiments, not genuine GPT decisions.

See [verification scope and actual counts](docs/VERIFICATION.md), the

or deployment is performed automatically.

## Source-bound Rail DSL addition

Actual controller source can now be inspected, edited, validated, reviewed,
explicitly applied, executed in native MuJoCo and independently replayed/audited.
The new controller project and old numerical projects have separate explicit
execution paths. The same physical scenario changed from wall-contact FAIL to
0.099 m clearance PASS through a source-only edit, with exact source/artifact mapping.
No native-bound historical file or acceptance threshold changed.

This is bounded Rail DSL, not arbitrary Python or a genuine AI qualification.
The source tools are provider-independent; all default proposals remain labelled
OFFLINE DETERMINISTIC ENGINEERING ASSISTANT. Historical failed qualifications,
accounting/reservations, artifacts and project heads are preserved. Archival
fixture-dependent failures remain documented, not silently skipped or fixed.
