# Context-aware engineering assistant · v0.9.1

Open a supported project, select genuine saved evidence, then open **Engineering
assistant** in the existing right inspector. This is a working deterministic tool
foundation. **Live reasoning has a separately approval-gated bridge; no genuine model test has qualified it.** Questions annotate
explicit local commands; they are not interpreted by a hidden model.

Use the normal `python -m tools.start` launcher. It mounts the bounded handler
extension over the existing product server. The legacy `python -m ide_api.server`
entrypoint keeps its older routes and does not mount the new assistant endpoints.
Both retain the same loopback Host/Origin/token guards and legacy execution rules.
The extension is part of broader application binding; native-bound server.py is
unchanged. There is no separate assistant application or native executor.

## Tools and contracts

`ide_api/engineering_agent.py` owns the strict input/output registry. Context
returns those schemas, typed fields/bounds and current evidence associations.
All calls have 24 KB input and 64 KB output ceilings; proposal retention is
bounded to 64 records with no automatic deletion. No tool reads arbitrary paths.

| Tool | Authority | Actual effect |
|---|---|---|
| `inspect_context` | Inspect | Exact project/head, numeric draft, selection, model/controller/environment, requirements and source/evidence metadata |
| `inspect_result` | Inspect/analyze | Strict saved reader and model-specific deterministic findings |
| `inspect_component` | Inspect | Actual selected compiled proxy component; no material or hardware certification |
| `compare_results` | Analyze | Compatible saved parameter comparison |
| `calculate_physics` | Analyze | Existing rail-only ideal calculation; zero native steps |
| `propose_parameters` | Propose | Immutable numeric review record after existing validation/compilation |
| `review_proposal` | Human review | Retain/reject only; not exposed to a model tool set |
| `prepare_verification` | Prepare only | Existing native request after human retention; not a model tool |
| `provider_status` | Inspect | Actual unavailable general-provider scope; creates no client |

Same-origin POST routes are `engineering-agent/context` and
`engineering-agent/tool`. There is no apply or HTTP approval route in
the deterministic tool registry. The separately gated live routes are described below. Extra fields, unsupported tools/parameters, nonfinite/bool
numbers, wrong identities and missing/corrupt evidence reject. Known model
validators, source-bound readers and physical predicates remain authoritative.
Returned schemas are internal tool contracts, not a claim of verified live
Responses protocol conformance.

Every action recomputes a context identity over the exact head, draft/criteria,
selection, selected evidence digest, registered native identity, current broader
application source manifest and Git base. Stale actions/reviews reject. Models
cannot accept their own proposals. The UI discards asynchronous results after
context changes and scopes bounded conversation history to that context.
Restored tab-local text remains an inspectable cache, not refreshed evidence or
review authority. Proposals are never restored as applied or auto-retained.

## Provider boundary

Existing `AgentOrchestrator` is controller/source oriented and can attach a
candidate verifier; it is not silently repurposed. Existing `EngineeringAI` /
`StudioExecution` scopes support mechanical assembly and bounded command repair.
`BudgetedOpenAIAdapter`, `DevelopmentBudget` and the credential factory retain
reservations, unknown-charge accounting, source/context binding, explicit
approval and no retry/fallback. None of those protected modules changed.

v0.9.1 extends the existing accounted request/gate architecture in unprotected
composition code. The protected adapters are unchanged. An API key, model output
or browser request cannot grant spending approval. Existing legacy workflows keep
their separate scopes. No genuine new AI success is claimed; the minimal real
read-only test is prepared for fresh explicit approval.

## Public checkout and physical limits

Existing reviewed public rail packages already demonstrate measured failure,
provenance, prediction and proposal preparation; no private qualification archive
is copied into Git. Local v0.8.1 rail/rover records remain available only where
legitimately retained. A clean checkout with no native jobs has honest empty
rover/native states; it does not gain prerecorded local-origin attestations.
Historical source evidence remains labelled, and never qualifies an edited draft
or changed application. Native compatibility and full application qualification
remain separate.

This is bounded numeric engineering over two registered proxies. General CAD,
electronics/firmware mutation, autonomous control, arbitrary source execution,
real-world material safety and live Agent-to-Physics are unsupported. SHAPEBASE,
CIRCUITBASE and the original mechanical studio retain their separate typed review
contracts. New simulation requires its own exact explicit authorization.

## Live provider bridge · v0.9.1

`EngineeringAgentLive` uses the existing `EngineeringAI.gate` validation, immutable
request Store, `DevelopmentBudget`, `BudgetedOpenAIAdapter` and pinned credential
factory. It does not replace the protected controller orchestrator or introduce
another provider client/accounting implementation. Actual raw request/response,
usage and sanitized failure receipts stay private. Costs calculated from reported
tokens are distinct from an invoice. Offline protocol doubles are visibly labelled
and never become genuine provider charges or physical measurements.

| Frozen profile | Model requests | Tool calls | Input reservation/request | Output/request | Hard USD cap | Maximum reservation |
|---|---:|---:|---:|---:|---:|---:|
| Inspect | 2 | 4 maximum | 49,152 | 4,096 | $0.40 | $0.36864 |
| Analyze / Propose | 3 | 4 maximum | 65,536 | 4,096 | $0.70 | $0.67584 |

Inspect offers only `inspect_result`: context already contains exact project/model,
controller IDs, environment, bounded fields/units and selected evidence. The model
must actually read the tool before its final explanation is accepted. Broader modes
add existing read/compare/rail calculation tools; Propose adds a strict one-parameter
adapter to the existing numeric proposal operation. That adapter maps the explicitly
documented `parameter`, `value`, `rationale` fields, never repairs an invalid model
argument. Human retain/reject, source, files, native execution and apply remain absent
from model tools. Accepted model proposals carry genuine provider/call provenance;
test-double proposals have explicit fixture provenance. All remain unapplied.

Only one serial tool call per provider response is accepted. Versioned strict
schemas and existing model validators check arguments independently. Each turn
binds current head/draft/selection/evidence/source/Git/dependencies/history and a
24-hour freeze. Requests reject critical context or output overflow rather than
truncating it. Total actual token ceilings are 106,496 / 208,896, respectively;
reasoning tokens are included in output cost. Tool outputs total at most 10 KB,
context at most 12 KB. The existing budget independently reserves before dispatch,
checks actual returned model/tier/usage, and retains unknown charges.

Structured final observations reference actual inspected result IDs, named metrics
and values (1e−12 numeric comparison tolerance); requirement references must match
actual check IDs/statuses. Unknown or altered references and proposal IDs reject,
without silently substituting real measurements. Free generated interpretation
and hypotheses remain unverified prose, never the physical verdict authority.
These checks do not constitute a semantic truth proof for all model language.

### Accounting and credentials

The operator-only history admission recovers the already approved genuine anchor,
its pinned leaf ledgers, its own genuine execution ledger and later actual workspace
ledgers. No QA fixture ledgers, aggregated reports or empty replacement baseline are
accepted as the production history. Duplicate responses and changed exposure fail
closed using the existing historical-accounting code. New current workspace/live
leafs invalidate pending scopes. History roots and file hashes remain private and
are never sent to the model or accepted as browser parameters.

The existing credential factory reads `OPENAI_API_KEY` or the owner-only project
`.env`, pins the destination, disables redirects/proxy overrides/retries and suppresses
transport logs. No key is copied from the original workspace. Credential/account
entitlement is checked only after approval; configuration of a bridge is not proof
that the account can invoke the model. Offline tools work without credentials.
Do not paste secrets or paths into the question. Context disclosure lets the user
review exactly what may leave the machine; obvious keys/paths/URLs reject.

Pricing was checked against the official
[GPT-5.4 model page](https://developers.openai.com/api/docs/models/gpt-5.4):
$2.50 input, $0.25 cached input and $15 output per million tokens for the bounded
standard-tier context used here. These match the installed approved policy, not a
new pricing implementation. Account access and live behavior remain untested.
The tool envelope follows the documented
[Responses function-calling flow](https://developers.openai.com/api/docs/guides/function-calling).

### Approval, execution and cancellation

Browser actions can prepare/read/cancel a turn. A trusted local operator records
actual fresh user approval of the exact manifest through
`tools.engineering_agent_live register-approval --request <id> --approval-file
<separately-recorded-approval>`. Making a JSON record or knowing the hash is not
consent; this is the existing trusted local-operator boundary, not a remote signature
service. No HTTP approval or client/transport injection endpoint exists.

Only that registered approval can unlock Start, which rechecks all gates and uses
the existing `Server.job` exclusion. A fixed trusted Python worker has a **180-second
supervised process deadline**; its parent kills an overrun and preserves unknown
usage rather than retrying. Provider calls have a 30-second timeout; tool checks
have a cooperative 20-second limit inside that hard worker boundary. No model can
change these limits. This is a single-operator loopback workflow, not distributed
multi-user/cloud billing enforcement.

Cancellation blocks further dispatches. An in-flight request may still be billed;
reported usage is settled, or its reservation remains unknown. Interrupted/consumed
scopes cannot restart. Source/head/evidence/accounting drift requires a different
frozen scope and fresh approval. Switching contexts abandons/cancels an unfinished
panel scope and prevents old model outputs becoming new-project actions. Saved
results stay immutable. Clearing the panel preserves the original request/evidence.

Model explanations link back to the current selected Verify and actual saved
trajectory views. Local deterministic evidence is displayed separately from model
interpretation. A compiled model-selected proposal still requires human review and
fresh, separately authorized physics. This release authorizes and performs neither
new paid calls nor native rollouts. The prepared minimal Inspect qualification is
not permission to execute it.

The frozen Responses request explicitly uses `store: true` to support provider
response continuity. The approved bounded task, context and tool results may
therefore be retained by the provider under its applicable data policy. Review
the exact first request before approval. Local cancellation or panel reset does
not delete provider-stored responses or local immutable evidence. No live request
was made during this implementation.

Live turn state survives locally as immutable request/evidence files; this version
does not restore its panel request ID after a full browser reload. Refresh is an
explicit bounded read, not streaming model activity. Historical accounting must be
legitimately admitted before live preparation; a clean checkout without the private
account history keeps live reasoning unavailable while deterministic tools work.
